# NetPulse 2.8 — рабочие разделы

Меню сгруппировано по задачам: обзор, сеть, работа отдела, защита и события,
инструменты и управление. Поиск раздела доступен через Ctrl/Cmd+K.
На телефоне меню закрывается кнопкой вне панели или Escape.

Каждый раздел содержит описание, справку об ограничениях и ссылки на связанные
задачи. «Обновить данные» читает состояние; сканирование, обучение модели,
блокировки, замеры скорости и RPC остаются отдельными явными действиями.

## Таблицы и данные

- Поиск по тексту и значениям полей, количество найденных строк, сортировка
  заголовками с естественным порядком чисел. Текстовый порядок IP удобен для IPv4,
  но не является полноценной сортировкой IPv6-адресов.
- Фильтр и сортировка сохраняются при перерисовке содержимого существующей таблицы.
  «Сбросить» очищает фильтр и снимает активную сортировку; порядок текущих строк
  остаётся до следующего ответа сервера.
- CSV выгружает отфильтрованные строки в текущем порядке, UTF-8 BOM, разделитель `;`.
  Начальные формулы обезвреживаются апострофом, поля паролей не выгружаются.
  Экспорт может содержать внутренние адреса и названия машин: храните его соответственно.
- Широкие таблицы прокручиваются внутри карточки; заголовки закреплены.
- Ответ сервера и свежесть измерения различаются. Общая строка состояния показывает
  время ответа; даты измерений остаются в самих данных. Неудачная загрузка явно
  предупреждает, что ранее показанные строки могут быть устаревшими.

## Изменения разделов

| Раздел | Изменение |
|---|---|
| Журнал | Поиск/сортировка работ и плана, CSV, переход к парку |
| Приложения | Фильтр процессов и пояснение ограничений process I/O |
| Соединения | Поиск и экспорт интерфейсов/соединений, переход к маршруту |
| Диагностика | Явное разделение ручных проверок и предупреждение о расходе трафика |
| Локальная сеть | Поиск/CSV, пояснение ARP, видимый результат перехода к скану портов |
| Парк ПК | Поиск в таблицах, пояснение источников агентских данных |
| Инфраструктура | Ссылки на инциденты и LAN, таблицы и состояние запросов |
| Меш | Отключённый/отсоединённый мост объясняется до запросов узлов; зависимые действия недоступны |
| Захват | Явное состояние запуска и оговорка об ОС/правах |
| Безопасность | Справка по ограничениям IDS и рискам блокировок |
| AI | Отсутствие аномалий не выдаётся за подтверждение исправности |
| Алерты | Текстовый поиск, новые/принятые, количество совпадений |
| История | Отдельные графики KB/s, задержки ms, джиттера ms, потерь %; пропуски и пустая история |
| Сисадмин | Контекст подключаемых источников, таблицы, переходы к парку/настройкам |
| Настройки | Предупреждение о черновике, сохранение полей при переходах, предупреждение при закрытии |

Черновик настроек живёт только в открытой странице; пароли и другие изменения
формы не записываются в localStorage. Успешное применение снимает предупреждение.

## P2P и HTTP-ошибки

`/api/p2pstatus` описывает мост даже когда он отключён. `ok: true` означает,
что запрос статуса выполнен, а не что решётка подключена. Для работы с узлами
нужны `enabled: true` **и** `connected: true`.

При выключенном модуле запросы узлов не отправляются из интерфейса. Прямой вызов
недоступного API сохраняет HTTP 503 и возвращает стабильный `code`:
`mesh_disabled`, `mesh_not_configured`, `mesh_disconnected`.
HTTP 502 означает сбой удалённого запроса после подключения.
Метрики удалённого хаба читаются RPC с хаба; CPU/RAM этого ПК не подставляются вместо них.

Включение: администратор настраивает секцию `p2p` в `config.json`, адрес/порт
ядра, идентификаторы и аутентификацию, запускает доверенное ядро и перезапускает
NetPulse. Интерфейс не включает модуль автоматически и не обходит аутентификацию.

Ошибки 400/403/404/409/429/500/502/503 имеют понятные пояснения. Внутренние тексты
исключений HTTP 500 не показываются пользователю. Код/имя конечной точки остаются
для диагностики; query string в сообщении ошибки не выводится.

## Проверки

`tests/workspaces.cjs` запускает настоящий Chromium: все 17 разделов,
1440px/390px, поиск, таблицы, CSV, фильтр алертов, DPR=2, черновик настроек,
503 и отключённый P2P. Табличные ответы в этой проверке синтетические; это не
испытание оборудования. Скриншоты и JSON-отчёт публикуются как artifact CI.

Существующие проверки операций, ролей, мониторинга и Linux-стенда сохранены.
Для локального запуска теста нужен изолированный `tests/browser_server.py`,
Playwright и `NP_TEST_URL` (по умолчанию порт 8796).
