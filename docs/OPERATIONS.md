# Операционный центр — NetPulse 2.5

В меню «Операционный центр» собраны устройства, площадки, ответственные,
инциденты, состояние самого NetPulse и история доставки уведомлений.
Все данные этого раздела сохраняются в SQLite и переживают перезапуск.

## Подключение MikroTik

Администратор задаёт ID, HTTPS-адрес, транспорт, имя отдельного пользователя
только чтения и **имя переменной окружения** с паролем. Сам пароль в браузер
и конфигурационный JSON не передаётся. Переменная должна быть доступна процессу
NetPulse; после её изменения перезапустите процесс. При частной CA укажите
путь к доверенному сертификату на сервере. Проверка сертификатов обязательна.

RouterOS 7 использует REST, RouterOS 6/7 — API-SSL. Старый challenge login
включается отдельно для выпусков до 6.43. Это поддержка протоколов, а не
утверждение о проверке каждого выпуска RouterOS на настоящем оборудовании.
Не включайте незашифрованный API ради подключения.

«Проверить подключение» выполняет чтение и показывает результат; сохранение
настроек само по себе не доказывает доступность устройства. Новые настройки
применяются при следующем опросе. Дополнительные таблицы DHCP, ARP, адресов,
VLAN, bridge hosts, PPP, health и Wi-Fi запрашиваются только при выборе.
Недоступная необязательная таблица не отменяет сбор основных показателей.

## Инциденты и права

Два последовательных отказа опроса открывают один инцидент на роутер.
Успешный опрос закрывает его. Повторения учитываются без создания дубликатов.
Можно назначить ответственного, принять инцидент в работу и добавить комментарий.
Техническое окно подавляет открытие новых автоматических инцидентов;
существующие записи не удаляются. Сводка охватывает последние 500 записей.

Администратор управляет подключениями и каналами. Оператор меняет контекст
устройств и инциденты. Наблюдатель читает данные; все POST-изменения запрещены.
Неизвестная или отсутствующая роль пользователя трактуется как viewer.
При обновлении проверьте явно заданные роли существующих пользователей.

## Prometheus, Grafana, Alertmanager

В `deploy/observability/secrets/` создайте три локальных файла:
`netpulse_metrics_token.txt`, `netpulse_alertmanager_token.txt`,
`grafana_admin_password.txt`. Используйте разные случайные значения.
Первое значение задайте процессу NetPulse как `NP_METRICS_TOKEN`,
второе — как `NP_ALERTMANAGER_TOKEN`. Файлы секретов исключены из Git.

Запуск: `docker compose -f deploy/observability/compose.yml up -d`.
Порты контейнеров опубликованы только на loopback. Prometheus собирает
кэшированные показатели, Grafana получает подготовленный дашборд,
Alertmanager отправляет события в `/api/alertmanager` с отдельным Bearer-токеном.
Этот токен не даёт доступ к остальному API. Локальный HTTP пример рассчитан
на Docker-host; при размещении на разных машинах настройте HTTPS с доверенной CA
и ограничьте сетевой доступ. Не публикуйте NetPulse в интернет без аутентификации.

Одинаковый MikroTikUnreachable от коллектора и Alertmanager объединяется;
Alertmanager не закрывает его, пока локальный коллектор фиксирует отказ.

## Доставка и диагностика

Уведомления идут только во включённые настроенные Telegram/webhook/email каналы.
Очередь ограничена, есть три попытки и журнал результата. Webhook требует HTTPS
и не следует перенаправлениям; SMTP по умолчанию использует STARTTLS; не отключайте TLS для передачи учётных данных. Статус sent означает
принятие транспортом, а не прочтение человеком. Внешняя доставка требует
реальных реквизитов канала и отдельной проверки у получателя.

`/healthz` и `/readyz` возвращают минимальный результат без секретов.
Подробная диагностика доступна авторизованному пользователю через `/api/health`.
Ошибка NVD отображается как незавершённая проверка CVE, а не «уязвимостей нет».
Совпадения по ключевым словам требуют проверки применимости к версии продукта.

## Границы текущей версии

Автотесты используют локальные TLS-имитаторы RouterOS. Тестовый стенд
`tests/browser_server.py` содержит явно синтетические данные и тестовые токены;
он не предназначен для эксплуатации. CI отдельно проверяет браузерные сценарии
и контейнерную цепочку Prometheus → Alertmanager → NetPulse плюс дашборд Grafana.
Доступ к настоящему MikroTik, проверка внешних каналов, восстановление из резервной
копии на отдельном узле и нагрузочное тестирование ещё нужны перед эксплуатацией.

Дальнейшие этапы: SNMP/LLDP-топология, корреляция зависимостей, расширенная
инвентаризация, управляемые сценарии с предварительным просмотром, полноценный
мастер резервного восстановления и нагрузочные профили. Они не считаются
реализованными только на основании этой версии.
