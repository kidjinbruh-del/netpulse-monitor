# Резервные копии и восстановление — NetPulse 2.6

Копия содержит **сохранённый config.json и согласованный снимок network_stats.db**.
Для работающей базы используется SQLite Backup API: записи в WAL попадают в снимок.
Каталог программы, node_modules, .git, .env и произвольные файлы не архивируются.
Это копия данных приложения, а не образ всей машины.

## Создать и проверить

В «Настройки → Резервные копии данных» администратор нажимает «Копия сейчас».
Действие выполняется в фоне. Через «Показать и проверить копии» можно проверить
SHA-256, размеры, формат config.json и SQLite integrity_check. Старые RAR и ZIP
с исходниками не имеют нового манифеста и не поддерживают эту проверку.
Их не конвертируют; обычная политика хранения может удалить старые копии.

CLI работает без запуска мониторинга и сетевых запросов:

```powershell
python -m netpulse --backup-create C:\NetPulseBackups --data-dir C:\NetPulseData
python -m netpulse --backup-inspect C:\NetPulseBackups\netpulse_auto_EXAMPLE.zip
```

`--data-dir` должен содержать оба файла данных. Отсутствующая база не создаётся.
Имя копии включает секунды и случайный суффикс. Готовый архив появляется после
завершения записи; ошибка не оставляет частично готовый ZIP в списке копий.
Параллельное создание внутри одного процесса запрещено. Разные процессы должны
иметь раздельные расписания и каталоги хранения.

Лимит распакованных данных — 2 GiB, конфигурации — 4 MiB, манифеста — 16 KiB.
Проверка отклоняет дубликаты, лишние файлы, пути вне архива и неверные суммы.
SHA-256 обнаруживает повреждения, но не доказывает подлинность: используйте
только копии из доверенного хранилища. Храните дополнительную копию вне диска сервера.

## Восстановление

Сначала установите ту же версию NetPulse. Выберите **новый, несуществующий** каталог,
родитель которого уже существует:

```powershell
python -m netpulse --backup-restore C:\NetPulseBackups\netpulse_auto_EXAMPLE.zip --restore-dir C:\NetPulseRecovered
```

Архив проверяется до создания каталога назначения. Существующий каталог, включая
пустой, не перезаписывается. При ошибке диска во время записи частичный результат
остаётся для диагностики — он не считается успешно восстановленным.
Веб-интерфейс не заменяет работающую базу: восстановление доступно через CLI.

Перед запуском восстановленного экземпляра:

1. Проверьте настройки адресов, каталога резервных копий, уведомлений и автоматизации.
   Изначально они указывают на прежнюю среду; тестовый экземпляр не должен выполнять
   действия на рабочей инфраструктуре или очищать её каталог копий.
2. Отдельно восстановите необходимые переменные окружения, CA, TLS-сертификаты,
   приватные ключи и идентичность меша. Эти файлы и секреты не включены в архив.
3. DPAPI-секреты из config.json читаются исходным профилем Windows на исходной машине.
   На другом профиле/сервере задайте новые токены и реквизиты; префикс dpapi: нельзя
   считать действующим паролем после переноса. Число таких значений выводит проверка.
4. Остановите прежний процесс перед переключением рабочего сервиса. Запускайте
   `python -m netpulse --check` из восстановленного каталога, используя установленный
   пакет или настроенный путь к исходникам. Затем запустите сервис из этого каталога.
5. Сверьте устройства, инциденты и журнал с ожидаемыми данными. Прежнюю установку
   сохраните до завершения проверки.

Восстановление не запускает приложение и не включает автоматизацию самостоятельно.

## Доступ и проверка

Архив может содержать пароли, токены, адреса и историю работы. Это **нешифрованный
ZIP-контейнер**; DPAPI защищает только те значения, которые уже были зашифрованы
в сохранённом config.json. На Windows настройте NTFS ACL каталога копий для
служебной учётной записи и администраторов; chmod не заменяет Windows ACL.
Не публикуйте архивы в GitHub. Для переноса используйте защищённое хранилище.

Автотесты проверяют сохранение записи, находящейся только в WAL, восстановление
в новый каталог, отказ от перезаписи, повреждения ZIP/JSON/SQLite и контрольных
сумм, пределы размера, права HTTP и отсутствие секретов в ответе проверки.
Браузерный тест выполняет создание и проверку через интерфейс. Это не заменяет
испытание восстановления вашей рабочей копии на отдельной машине.
